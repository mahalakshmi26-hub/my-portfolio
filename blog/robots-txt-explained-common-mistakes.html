Robots.txt Explained: What It Does and Common Mistakes

M
Mahalakshmi Marimuthu
· 6 min read · July 2026

A single wrong line in your robots.txt file can quietly deindex your entire website — and most site owners never even open it. Here's what this small file actually does, and the mistakes that trip up beginners most often.

What is Robots.txt?

Robots.txt is a small text file that sits at the root of your website (yoursite.com/robots.txt) and gives instructions to search engine crawlers about which parts of your site they're allowed to access.

Think of it as a sign posted at the entrance of your house that says "please don't go into the garage" — most polite visitors (like Googlebot) will respect it. It doesn't lock the door; it just asks nicely.

User-agent: *
Disallow: /admin/
Disallow: /cart/
Allow: /

Sitemap: https://example.com/sitemap.xml

What Robots.txt Actually Controls

  • Crawling, not indexing. It tells bots where they can and can't go — it does not remove pages from Google's index by itself.
  • Crawl budget. On large sites, blocking low-value pages (admin panels, filters, search result pages) helps search engines spend their crawl time on pages that matter.
  • Bot-specific rules. You can write different rules for different crawlers using User-agent, though most sites just use * for "all bots."
Common misconception: blocking a page in robots.txt doesn't guarantee it disappears from Google. If other sites link to that page, Google can still index the URL — just without crawling its content. To fully remove a page from search results, use a noindex meta tag instead.

Common Mistakes That Hurt SEO

1. Accidentally blocking the entire site

This is the most damaging mistake — often left over from a staging or development site:

User-agent: *
Disallow: /

That single line tells every search engine to stay away from every page on your site. It's shockingly common after a site migration or redesign, when developers forget to remove this before going live.

2. Blocking CSS and JavaScript files

Older advice suggested blocking resource files, but modern Google needs to render your CSS and JS to understand your page properly. Blocking them can hurt how your pages are evaluated.

3. Using robots.txt to hide sensitive content

Robots.txt is a public file — anyone can view it by visiting the URL directly. Listing private folders there (like /admin/) can actually draw attention to them. Sensitive areas need real authentication, not just a polite request to bots.

4. Forgetting the sitemap reference

Adding a line pointing to your sitemap makes it easy for crawlers to find:

Sitemap: https://example.com/sitemap.xml

5. Confusing Disallow with Noindex

Disallow (robots.txt) Noindex (meta tag)
Stops crawling of the page Allows crawling, but removes from search results
Page can still appear in search if linked elsewhere Page is reliably excluded from search results
Set in the robots.txt file Set in the page's HTML <head>

How to Check Your Robots.txt

  1. Visit yoursite.com/robots.txt directly in your browser to see the live version.
  2. Use Google Search Console's robots.txt report to confirm Google can read it without errors.
  3. After any site migration or redesign, always double-check this file before and after launch.
The takeaway: robots.txt is simple but high-stakes — a small file with the power to make your entire site invisible if written carelessly. Check it after every major site change, and never assume it's still correct just because no one touched it recently.
